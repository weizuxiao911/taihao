三、CI 冒烟四条红线

1 · 禁止业务硬件模拟驱动内置
SPI / I2C / GPIO / V4L2 / CAN / SocketCAN / PWM / WATCHDOG / hwmon 等接入位接口一律不进 CI 内核,防止 CI 隐性依赖 HAL 硬件节点。
2 · 禁止内核模块
CONFIG_MODULES=n,杜绝"模块缺失"漏测。
3 · 禁止兼容 cgroup v1
统一 cgroup v2 单一模式,systemd 不开 v1 fallback。
4 · 禁止业务共享目录
virtio-9p / virtio-fs 不进 CI;主机目录共享仅 E2E 调试启用。

七、qemu 快照策略

0 · 状态盘承载savevm / loadvm 需要可写块设备落盘。e2e 构建阶段产出 out/arm64-e2e/snap/boot-snap.qcow2(256M 状态盘),qemu 挂 -drive file=...,if=virtio,format=qcow2,快照写入该盘,与 rootfs 无关
1 · 首次冷启动保存 vmstate + memory 到状态盘,标记为 boot-snap;命令:qemu-start-e2e.sh --save-snap(或 save-snap 子命令)
2 · 增量迭代ccache 命中 → 增量编译 → 替换内核镜像 → loadvm boot-snap 快速重启;启动脚本自动判定快照有效性后加载
3 · 快速回退验证失败 → loadvm boot-snap 立即回退,无需重新初始化;命令:qemu-start-e2e.sh load-snap
4 · 失效判定Image / initramfs / 状态盘三路 sha256 哈希比对;任一变更 → 旧快照强制失效;删除状态盘重新冷启,命令:qemu-start-e2e.sh reset-snap
关键约束：loadvm 不能切换内核镜像。内核内存镜像与磁盘镜像不一致会引发不可复现异常。
